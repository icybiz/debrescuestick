Before you start

Which computers and networks are supported?

The current base uses Debian 13 for 64-bit x86 computers (amd64). Automated tests cover booting as a virtual USB drive with BIOS and UEFI, DHCP, and SSH access with the owner's key. Test guests use 1 GiB of RAM. Secure Boot has also been tested in a virtual machine with enrolled Microsoft certificates: the signed system boots with kernel lockdown enabled, and an unsigned bootloader is rejected. Individual physical computer models have not been tested yet.

Connect the target computer to a wired network with DHCP. Its IP address must be reachable from your computer. The extracted image is about 8 GiB; use a USB stick with a nominal capacity of at least 16 GB.

How do I write the image to a USB stick?
  1. Download the ZIP file, verify its SHA-256 checksum, and extract DebRescueStick-amd64.img.
  2. Select the intended USB stick as the whole target device. Writing the image replaces its existing contents.
  3. Write the image using a disk image writer. On Windows 8 or later, for example, you can use Rufus and write the IMG file in DD mode.
  4. Boot the target computer from the stick. The local rescue console shows its network addresses and SSH host key fingerprints. Connect with ssh root@IP-ADDRESS; for a private key in a different location, use ssh -i PATH-TO-PRIVATE-KEY root@IP-ADDRESS.

Linux (GNU dd)

Open a terminal in the directory containing the extracted IMG file. Identify the USB stick with lsblk -o NAME,SIZE,MODEL,TYPE,MOUNTPOINT. Unmount every mounted partition of that stick first, for example with sudo umount /dev/sdX1. Replace /dev/sdX below with the whole USB device, not a partition such as /dev/sdX1.

sudo dd if=DebRescueStick-amd64.img of=/dev/sdX bs=4M conv=fsync,nocreat status=progress

macOS

Find the USB stick with diskutil list. Replace N in both /dev/diskN and /dev/rdiskN with its disk number. The commands unmount the stick, write the extracted image, finish pending writes and eject it. While dd is running, Control+T can show progress.

diskutil unmountDisk /dev/diskN &&
sudo dd if=DebRescueStick-amd64.img of=/dev/rdiskN bs=4m &&
sync &&
diskutil eject /dev/diskN

Other Unix systems, including BSD

Identify the USB device using your system’s disk tools and unmount all its partitions. Replace /dev/USB_DEVICE with the whole USB device. This form uses a numeric block size and omits GNU-specific progress options.

sudo dd if=DebRescueStick-amd64.img of=/dev/USB_DEVICE bs=1048576 && sync

All existing data on the selected target is replaced. Run these commands with the extracted IMG, not the ZIP file, and wait for successful completion before removing the stick. Creating a stick on macOS does not change the image’s x86-64 (amd64) boot requirement.

What happens to my download?

The prepared system is reused; only the small key partition is personalized for you. The download link is valid for two hours from the time you submit your request. This is the download window, not the preparation time. The request, submitted public key, and personal download are removed after expiry. Treat the download link as personal and share it only deliberately.

How long will my rescue stick work?

A downloaded image and the stick written from it remain usable after the download link expires. The stick keeps your public SSH key. You will still need the matching private key to sign in.

What will be overwritten on the USB stick?

Writing a disk image replaces the contents of the selected USB stick. Check the target device carefully before writing.

Where are the licences and source packages?

Licence and copyright notices for the included packages are available in the image under /usr/share/doc and /usr/share/common-licenses. Corresponding original sources, Debian changes, and DSC files are provided permanently for every published base. Follow the source packages link in the footer.

What happened to SystemRescueImage?

The earlier project prepared SystemRescueCd files as directly writable USB images. DebRescueStick is an independent project based on Debian, focused on SSH access prepared with your own key.
